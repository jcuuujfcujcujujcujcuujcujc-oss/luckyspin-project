# Паспорт проекта LuckySpinAPI

| Поле | Содержание |
|------|-----------|
| Название | LuckySpinAPI |
| Проблема | Для учебной игры в слот нужен единый серверный API, который хранит баланс игрока, честно считает результат вращения и не позволяет накручивать кредиты |
| Пользователи | Игрок, оператор |
| SMART-цель | За 4 учебные недели довести LuckySpinAPI до прототипа с четырьмя функциями MVP (баланс, ставка, выигрыш, проверка ставки) и не менее чем 5 автоматическими тестами |
| MVP | Просмотр баланса; ставка и вращение; начисление выигрыша; отклонение некорректных ставок |
| Не входит в MVP | Реальные деньги и платёжные системы; регистрация с паролями и авторизация по токенам; админ-панель оператора; внешняя СУБД; мобильный клиент |
| Критерии приёмки | API запускается; все 4 функции MVP работают; 5+ тестов проходят; отрицательная ставка не меняет баланс |
| Ограничения | Учебные ресурсы и время; игра только на виртуальные кредиты; платформа .NET Core 3.1; данные в памяти |
| Результат | Репозиторий GitHub с работающим кодом, документацией и историей изменений |

Сроки в 4 недели служат учебным примером и не являются обязательным сроком курса.

## Проблема и целевая аудитория

Сейчас в проекте есть работающий прототип, но он позволяет вводить отрицательную ставку и тем самым увеличивать баланс, логика выигрыша дублируется в двух местах, тестов нет. Игроку нужна предсказуемая игра, оператору нужен контроль над игроками.

## Функции будущего продукта

1. Просмотр баланса (обязательно)
2. Ставка и вращение (обязательно)
3. Начисление выигрыша (обязательно)
4. Проверка ставки (обязательно)
5. История игр игрока (дополнительно)
6. Управление игроками оператором (дополнительно)

## Критерии успешности проекта

| № | Критерий | Как измерить |
|---|----------|-------------|
| 1 | Не менее 5 автоматических тестов проходят | `dotnet test` |
| 2 | Ставка `<= 0` отклоняется во всех проверочных случаях, баланс не меняется | Тесты и ручная проверка через Swagger/curl |
| 3 | Все 4 функции MVP доступны через API | Приёмочная проверка по docs/REQUIREMENTS.md |
| 4 | Документация согласована: каждое требование из MVP связано с Issue | Проверка ссылок в docs/ |
