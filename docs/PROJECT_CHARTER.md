# Паспорт проекта LuckySpinAPI

| Поле | Содержание |
|------|-----------|
| Название | LuckySpinAPI |
| Проблема | Для учебной игры в слот нужен единый серверный API, который хранит баланс игрока, честно считает результат вращения и не позволяет накручивать кредиты |
| Пользователи | Игрок (в MVP), оператор (версия 2) |
| SMART-цель | С 09.11.2026 по 04.12.2026 (4 учебные недели) довести LuckySpinAPI до прототипа с четырьмя функциями MVP (баланс, ставка, выигрыш, проверка ставки) и не менее чем 5 автоматическими тестами |
| MVP | Просмотр баланса; ставка и вращение; начисление выигрыша; отклонение некорректных ставок |
| Не входит в MVP | Реальные деньги и платёжные системы; регистрация, пароли и авторизация по токенам; роли и операторские функции (список игроков, блокировка); история игр; внешняя СУБД; мобильный клиент |
| Критерии приёмки | API запускается; все 4 функции MVP работают; 5+ тестов проходят; отрицательная ставка не меняет баланс |
| Ограничения | Учебные ресурсы и время; игра только на виртуальные кредиты; данные в памяти |
| Результат | Репозиторий GitHub с работающим кодом, документацией и историей изменений |

## Граница MVP и версии 2

В MVP нет регистрации и авторизации: игрок определяется числовым `userId`. Поэтому всё, что требует паролей и ролей, относится к **версии 2**: требование NFR-01 (хеши паролей, доступ оператора), FR-06 и FR-07 (операторские функции) и истории US-05, US-06.

## Проблема и целевая аудитория

Исходный прототип позволял вводить отрицательную ставку и этим увеличивать баланс, логика выигрыша дублировалась, тестов не было. Игроку нужна предсказуемая игра, оператору (в версии 2) нужен контроль над игроками.

## Функции будущего продукта

1. Просмотр баланса (MVP)
2. Ставка и вращение (MVP)
3. Начисление выигрыша (MVP)
4. Проверка ставки (MVP)
5. История игр игрока (после MVP)
6. Управление игроками оператором (версия 2)

## Критерии успешности проекта

| № | Критерий | Как измерить |
|---|----------|-------------|
| 1 | Не менее 5 автоматических тестов проходят | `dotnet test` |
| 2 | Ставка ≤ 0 отклоняется во всех проверочных случаях, баланс не меняется | Автотесты и ручная проверка через страницу игры |
| 3 | Все 4 функции MVP доступны через API | Приёмочная проверка по docs/REQUIREMENTS.md |
| 4 | Каждое требование MVP связано с Issue, а Issues закрыты после проверки | Список Issues и Milestones на GitHub |

## Согласование и приёмка

**Согласование требований.** Паспорт и docs/REQUIREMENTS.md считаются утверждёнными, когда заказчик оставил комментарий «Утверждаю» в Pull Request или Issue с этим документом; дата и версия фиксируются в таблице согласования в конце REQUIREMENTS.md.
