# Пользовательские истории

Шкала оценки Story Points: 1, 2, 3, 5, 8. Приоритеты по MoSCoW. Общий стандарт завершения: [Definition of Done](DEFINITION_OF_DONE.md).

## Эпик → истории

Эпик «Оператор управляет игроками» был слишком крупным, поэтому разбит на две независимые истории: US-05 (просмотр списка) и US-06 (блокировка). Каждую можно реализовать и проверить отдельно.

## US-01. Просмотр баланса ([Issue 6](../../../issues/6))

**Как игрок, я хочу видеть свой баланс, чтобы понимать, сколько могу поставить.**

- Баланс отображается сразу после загрузки страницы
- Новый игрок видит 1000 кредитов
- После каждого вращения баланс обновляется без перезагрузки

Связь: FR-01 · Must · 2 SP

## US-02. Ставка и результат ([Issue 7](../../../issues/7))

**Как игрок, я хочу сделать ставку и увидеть результат вращения, чтобы играть в слот.**

- Игрок видит три символа и сообщение о выигрыше или проигрыше
- Ставка списывается, выигрыш начисляется
- Результат приходит одним ответом API

Связь: FR-02, FR-03 · Must · 3 SP

## US-03. Понятная ошибка при неверной ставке ([Issue 8](../../../issues/8))

**Как игрок, я хочу получать понятную ошибку при неверной ставке, чтобы исправить её и не потерять кредиты.**

Критерии в формате Given/When/Then, включая ошибочный ввод:

- **Given** игрок с балансом 1000, **When** он отправляет ставку -100, **Then** ответ 400 с понятным сообщением, баланс остаётся 1000
- **Given** игрок с балансом 50, **When** он ставит 100, **Then** ответ 400 «Недостаточно кредитов на балансе», баланс остаётся 50
- **Given** ставка 0, **When** отправлен spin, **Then** ответ 400 и запись в историю не создаётся
- **Given** несуществующий игрок, **When** отправлен spin, **Then** ответ 404 с сообщением, игрок не создаётся

Связь: FR-04 · Must · 2 SP (негативный сценарий)

## US-04. История вращений ([Issue 9](../../../issues/9))

**Как игрок, я хочу видеть историю своих вращений, чтобы контролировать свою игру.**

- Каждое вращение попадает в историю с датой, ставкой, комбинацией и выигрышем
- Выводятся последние 20 записей, новые сверху
- Для игрока без вращений возвращается пустой список

Связь: FR-05 · Should · 5 SP

## US-05. Список игроков для оператора ([Issue 10](../../../issues/10)) — версия 2

**Как оператор, я хочу видеть список игроков и их балансы, чтобы контролировать состояние системы.**

- GET /api/admin/users возвращает Id, Username, Balance, IsBanned
- Пароли и хеши в ответе отсутствуют
- Запрос без роли Operator получает 403

Связь: FR-06, NFR-01 · Should · 3 SP · версия 2 (нужны роли и аутентификация, которых нет в MVP)

## US-06. Блокировка игрока ([Issue 11](../../../issues/11)) — версия 2

**Как оператор, я хочу блокировать игрока, чтобы пресекать нарушения правил.**

- Заблокированный игрок при spin получает 403
- Оператор может снять блокировку
- Блокировка несуществующего игрока возвращает 404

Связь: FR-07, NFR-01 · Should · 5 SP · версия 2

## Проверка по INVEST

Истории независимы настолько, насколько позволяет предметная область (US-04 зависит от записи GameLog, US-05 и US-06 от модели ролей), оцениваемы и проверяемы. Распределение по ролям: игрок US-01…US-04, оператор US-05, US-06.
