# Спецификация требований

Роли: **Игрок**, **Оператор**. Приоритеты по MoSCoW. Числовые пороги учебные и подлежат согласованию.

В колонке «Статус» отмечено текущее состояние кода на момент составления документа.

## Функциональные требования

| ID | Требование | Приоритет | Проверка | Статус в коде | Issue |
|----|-----------|-----------|----------|---------------|-------|
| FR-01 | Игрок получает баланс по userId; для нового userId создаётся игрок с балансом 1000 | Must | GET /api/slots/balance/1 возвращает 200 и `balance` | Реализовано | [Issue 1](../../../issues/1) |
| FR-02 | Игрок совершает ставку: система списывает ставку и возвращает комбинацию, новый баланс, признак выигрыша и сумму выигрыша | Must | POST /api/slots/spin с валидной ставкой возвращает 200 и все поля | Частично | [Issue 2](../../../issues/2) |
| FR-03 | Если три символа совпадают, система начисляет выигрыш ставка × 5; иначе выигрыш 0 | Must | Тест с подменённым генератором: совпадение и несовпадение | Реализовано | [Issue 3](../../../issues/3) |
| FR-04 | Система отклоняет ставку ≤ 0, ставку выше баланса и ставку несуществующего игрока (400 / 404) без изменения баланса | Must | Тесты: ставки -100, 0, больше баланса; неизвестный userId | Не реализовано (для ≤ 0) | [Issue 4](../../../issues/4) |
| FR-05 | Игрок просматривает последние 20 своих вращений (дата, ставка, комбинация, выигрыш) | Should | GET /api/slots/history/{userId}: порядок и количество записей | Не реализовано | [Issue 5](../../../issues/5) |
| FR-06 | Оператор просматривает список игроков с балансами и признаком блокировки | Should | GET /api/admin/users возвращает список без паролей | Не реализовано | через [US-05](../../../issues/10) |
| FR-07 | Оператор блокирует и разблокирует игрока; заблокированный не может делать ставки | Should | После блокировки spin возвращает 403 | Не реализовано | через [US-06](../../../issues/11) |
| FR-08 | Оператор корректирует баланс игрока с указанием причины; операция записывается в журнал | Could | Баланс изменён, запись в журнале существует | Не реализовано | нет Issue (вне итерации 1) |

## Нефункциональные требования

| ID | Категория | Требование | Приоритет | Проверка |
|----|-----------|-----------|-----------|----------|
| NFR-01 | Безопасность | Пароли хранятся только в виде хеша (PasswordHash); методы оператора /api/admin/* доступны только роли Operator, остальным возвращается 403 | Must | Проверка реализации хранения; тест доступа без роли |
| NFR-02 | Производительность | При 50 одновременных запросах POST /api/slots/spin 95% запросов выполняются не дольше 300 мс на тестовой машине разработчика | Should | Нагрузочный тест с замером перцентиля |
| NFR-03 | Надёжность | При 20 параллельных ставках одного игрока итоговый баланс равен расчётному и никогда не становится отрицательным | Must | Параллельный тест на одном userId |
| NFR-04 | Удобство | Каждый ответ с ошибкой содержит HTTP-код и сообщение на русском языке, понятное без чтения кода; все методы описаны в README | Should | Проверка ответов в тестах; ревью README |

## Различие требований и решений

В список не включены технические решения. Например, «использовать Entity Framework Core InMemory» относится к реализации и описано в README, а требование NFR-03 описывает поведение системы.

## Проверка качества

- Слова «быстро» и «удобно» заменены измеримыми порогами (NFR-02, NFR-04)
- Дубли и конфликты не обнаружены: FR-02 описывает ставку, FR-03 выплату, FR-04 ошибки ввода
- Требования атомарны: у каждого одна проверяемая цель

## Известное отклонение кода от требований

Сейчас `SlotsController` не проверяет `betAmount > 0`: отрицательная ставка прибавляет кредиты. Это нарушение FR-04, оно вынесено в историю [US-03](../../../issues/8) и первую итерацию.
